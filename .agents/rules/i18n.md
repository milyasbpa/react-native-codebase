# 🌐 Rule: Internationalization (i18n) & Multi-Language Standard

## 1. i18n Configuration Rule
- Library stack: `i18next` + `react-i18next`.
- Default language: `en` (English) with fallback support for `id` (Indonesian).
- User language preference persistence MUST be synced with `AsyncStorage` key `@user_language`.

## 2. Namespace Organization Rule
- **`core`**: Contains shared global translations (`src/core/i18n/locales/en.json` & `id.json`) for universal labels such as *Cancel, Save, Delete, Loading, Error, Success, Retry*.
- **`<feature>`**: Contains domain-specific strings located in `src/features/<feature>/i18n/en.json` & `id.json`.

## 3. Usage in Components
Utilize the `useTranslation` hook explicitly specifying the relevant namespace:
```tsx
import { useTranslation } from 'react-i18next';

export const ProductCard = ({ product }) => {
  const { t } = useTranslation('product');

  return (
    <View>
      <Text>{t('price_label')}: ${product.price}</Text>
    </View>
  );
};
```
- Hardcoded user-facing UI text strings directly in JSX elements are strictly prohibited when multi-language support is enabled.
